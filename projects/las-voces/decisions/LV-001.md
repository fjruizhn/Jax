**DECISIÓN — Fernando, 2026-10-03, vía jax-14.** LV-001A quedó integrado en

**LV-001B ratificado:** Qwen Code local descubre y lee el paquete/contrato de
El Faro por una interfaz MCP aislada de solo lectura. La interfaz ofrece las
lecturas que el Puerto ya expone: `skills.buscar`, `skills.leer`,
`agentes.listar`, constitución y recursos de skill/agentes. No ofrece control,
creación de ejecuciones, lanzamiento de misiones, mutación, obtención de
credenciales ni concesión de autoridad. La primera misión Qwen gobernada por
Faro es un hito separado. `jaxqwen` permanece intacto.

**Implementación:** `.qwen/settings.json` del proyecto fija
`model.generationConfig.contextWindowSize=131072` y registra el servidor MCP
`faro-readonly`. `authority/faro_readonly_mcp.py` carga el paquete de Faro con
`ConfigFaro.desde_entorno` y `cargar_paquete`; si faltan configuración,
propietario/integridad o bytes verificados, se detiene antes de abrir MCP. El
servidor solo contiene una lista fija de métodos y herramientas de lectura.
No abre el socket de control ni recibe el token de una ejecución del Puerto.
Las rutas del paquete se resuelven como claves exactas de memoria, nunca como
rutas del host. El paquete debe haber sido construido y contrastado con el
árbol Git por el constructor de Faro; este lector no hace ese contraste.
Al arrancar Qwen desde `projects/las-voces/` deben estar presentes
`JAX_FARO_REPO`, `JAX_FARO_SHA` y `JAX_FARO_ECOSISTEMA_DIR` de un paquete ya
construido. La aprobación de confianza de carpeta que Qwen exige para servidores
MCP del proyecto es un paso de uso local; `trust: false` conserva las
confirmaciones de herramientas. Sin paquete disponible el servidor falla
cerrado y Qwen no recibe herramientas Faro.

**Límite declarado:** el MCP no es una jaula ni una identidad nueva. Qwen y los
otros motores locales comparten hoy el uid `fruiz`; las herramientas nativas de
Qwen conservan su alcance normal. Por ello esta interfaz no afirma que una
sesión Qwen completa esté confinada ni que una misión esté gobernada por Faro.
El control de credenciales, jaula, identidad y reglas vigentes pertenece al hito
de primera misión y a las fases propias de Faro.

**Contexto efectivo:** la preferencia `~/.qwen/settings.json` no es prueba.
El proyecto fija 131072 y la prueba con el resolvedor real de Qwen Code 0.24.7
registra el valor fusionado y resuelto. Si una configuración de proveedor o
sistema reemplaza ese valor, la comprobación debe quedar roja antes de aceptar
la sesión. Una instalación nueva debe volver a medirlo.

**Criterios de aceptación:** son los ocho campos `acceptance_criteria` de la
tarea LV-001 en `project.json`. `READY` se mantiene hasta que la evidencia de
CI, el commit/PR exacto y la aceptación de Fernando cumplan el contrato LV-003.
Un test local o un veredicto de auditoría no transforman por sí solos la tarea
en `DONE`.
