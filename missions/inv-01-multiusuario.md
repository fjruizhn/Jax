# INV-01 — crabfleet: arquitectura multi-usuario

Investiga cómo el proyecto **crabfleet** de OpenClaw (github.com/openclaw/crabfleet) maneja MÚLTIPLES usuarios/operadores. Es clave para nosotros porque queremos que varias personas interactúen con el sistema, no solo un operador.

Responde SOLO estas preguntas, con URL de fuente para cada una. Sé concreta:

1. ¿Cómo maneja crabfleet la autenticación de usuarios? (login, GitHub OAuth, tokens, etc.)

2. ¿Cómo separa o agrupa el trabajo por persona? (vimos "org Codex instances grouped by person" — cómo funciona eso exactamente)

3. ¿Tiene roles o niveles de permiso distintos para diferentes usuarios? (admin, operador, observador, etc.)

4. ¿Cómo evita que un usuario vea o toque el trabajo de otro? ¿O todos ven todo?

5. ¿Cómo maneja sesiones concurrentes — varias personas usando el sistema al mismo tiempo?

Para cada respuesta: URL de la fuente. Si no encontrás algo, decílo con honestidad — no inventes. Prefiero "no encontré esto" a un dato fabricado.
